about



The whole website runs on the fact that images with transparency can represent 3D objects at a lower memory cost (but reduced accuracy) than traditional 3D models. This allows highly complex models to be used as simple 2D textures instead of loading them as geometry files.

Things possible with images that are not possible with 3D objects: image comparing, image layering, more efficient optimization by removing duplicates (which there are many of), post-processing effects (sharpen, overlay, dither, animate), etc.

Supported extensions: png, jpg, gif, html

The whole website acts as a folder structure with folders and content inside. Files can propagate through these folders — they can "bubble up" to the surface. This is the case for both images and text documents.





Bubbling up



Throughout the folder structure, text and image files bubble up — files in child folders are accumulated as you traverse upward through the directories. At the root (archigrad.io), images are turned into stacks and groups, so all images across the website are visible at the root level.

HTML files behave the same way, but there are two flags to control this, since accumulation is not always desired. For images there is no such control — all images will always bubble up.

How do I stop my HTML from bubbling up?

.html_only_here — HTML stays at this level only and does not propagate upward.

How do I stop all HTML from bubbling up?

.html_stops_here — No HTML passes through this folder upward.

Place an empty file with either name in any directory. The content does not matter, only its presence. The easiest way is to create a new file and name it .html_stops_here or .html_only_here.

These are represented as colored dots in the tree view and breadcrumb labels:



  • Blue dot — .html_only_here is present in this folder
  • Green dot — .html_stops_here is present in this folder
  • White dots (or colored if COLORED_HTML_DOTS = True) — each dot represents one accumulated HTML file. When enabled, each HTML file gets a deterministic random color based on its path and SEED, so the same file always appears as the same color across all nodes it propagates through.

How to add images?


Create a folder inside archigrad.io or any child folder and put images in it.


Allowed: all files need to be in folders

v archigrad.io v projects image1.png image2.png

Not allowed — a folder cannot contain both subfolders and images:

v archigrad.io v projects v project_1 image1.png imagea.png ← not allowed alongside a subfolder

How to add 3D models?

The website does not load 3D models — only textures. 3D models can be sliced and recreated as a 2D version stored on a spritesheet.

All images are loaded from a single spritesheet so only one request is needed to fetch potentially hundreds of images. The spritesheet is stored as a .ktx2 file which does not need to be decompressed on the GPU — saving about 4× memory over PNG. GIFs are stored on this sheet as multiple frames laid out sequentially.

How do I make a stack?

Put images in a folder. Images are sorted alphabetically, with the first image at the bottom of the stack.

Two suggested workflows:



  1. Under the archigrad.io folder, add images to a named folder in the desired order.
  2. Optionally place a .custom_processing file next to them with adjusted settings.
  3. Run the script.
  4. The stack is now visible.


  1. Open the Houdini file, load your model, pick your size, and render out the stack frames.
  2. Optionally place a .custom_processing file next to them (can be exported from the HDA).
  3. Run the script.
  4. The stack is now visible.

Adding 3D models via Houdini

Only flipbook rendering is used — OpenGL and Karma are too slow to be practical. Whatever is visible in the viewport will be shown, including attributes, visualizers, and all viewport shading settings.

Static geometry

  1. Build geometry in Houdini and use the HDA to export it.
  2. Alternatively, bake a texture in Blender, import the model into Houdini, and apply a constant shader with that texture.

You can also export your .custom_processing file from the HDA.

Animated geometry

Same as static, but set the keyframe range for the desired number of frames. The maximum is currently 30 (configurable via MAX_GIF_FRAMES). Animated geometry is converted to GIFs and laid out on the spritesheet.

Known limitation: if a GIF spans more than one spritesheet (e.g. 500 frames, sheet only fits 400), the overflow frames will glitch. Lower MAX_GIF_FRAMES if this occurs.



How do I customize my image stack?



Everything is controlled by two things: a per-folder .custom_processing file, and the global defaults in file.py. If no .custom_processing is present, global defaults are used. You can place this file anywhere in a folder — next to images or in a subfolder.

global defaults — these can be set in python only. if they are set they are considered the defualts. if you cont have a .custom_procesing file, then these settings will be applied. there are some gloabls vars that are exclusivly set here.


# spritesheet
SPRITESHEET_SIZE=4096
Max pixel dimension of each spritesheet. All sprites are packed into sheets of this size. Larger = fewer sheets but bigger files.
default: 4096
SPRITE_SIZE=64
Size in pixels of each image on the spritesheet. All images are resized to this before packing. Higher = sharper but more memory and spritesheet space.
default: 64
RESIZE_METHOD=Image.LANCZOS
Downscaling algorithm when resizing images to SPRITE_SIZE. LANCZOS is high-quality. Not user-facing — hardcoded.

• LANCZOS — highest quality downscaling, slowest
• BICUBIC — good quality, faster than LANCZOS
• BILINEAR — moderate quality, fast
• NEAREST — no interpolation, pixelated, fastest
• BOX — simple averaging, good for large downscales
• HAMMING — between BILINEAR and BICUBIC
default: Image.LANCZOS
LABEL_SPRITE_SIZE=512
Sprite size specifically for text label images on spritesheets. Separate from SPRITE_SIZE so labels can be sharper. Overridden to 128 in low-res mode.
default: 512
# LOD
LOD_TARGET_SPRITE_SIZES=[None, 32, 8]
Level of Detail tiers. LOD0 = original resolution, LOD1 = 32px per sprite, LOD2 = 8px. Viewer swaps to lower-res sheets when zoomed out to save GPU memory.
default: [None, 32, 8]
LOD_VIEWHEIGHT_THRESHOLDS=[20, 40]
Camera viewHeight thresholds for LOD switching. Below 20 → LOD0. Below 40 → LOD1. Above 40 → LOD2.
default: [20, 40]
# viewer
STACK_DIM_OPACITY=0.35
Opacity of non-active stacks when navigating into a folder. 0.0 = invisible, 1.0 = fully visible.
default: 0.35
SEED=2922
Global seed for all deterministic randomness: colored HTML dots, random zoom values, random text/image div positioning.
default: 2922
QUICKLOAD_THRESHOLD=100
Passed to viewer config but not currently used in JS. Reserved for a future loading strategy switch based on image count.
default: 100
ORDERED_GRID_LAYOUT=True
When True, stacks are arranged in a grid using each node's grid_layout property (e.g. "3x2"). When False, layout is free-form.
default: True
ROTATION_SPEED=0.000015
Auto-rotation speed of the entire 3D scene on the Y axis. Very small values = slow ambient rotation.
default: 0.000015
RANDOM_ZOOM=False
When True, each page gets a random zoom level (0.1, 0.4, or 1.0) seeded by SEED. When False, uses ZOOM_VALUE. Per-node zoom always overrides both.
default: False
ZOOM_VALUE=0.4
Default camera zoom level. Smaller = more zoomed in, larger = more zoomed out.
default: 0.4
RANDOM_TEXTDIV_POSITION=False
When True, left/right order of text and image divs is randomized per folder using SEED. When False, text is always left, images right.
default: False
DIV_RATIO_HALF=False
With exactly 2 children (text + image) on desktop: False = asymmetric 40/60 split. True = 50/50.
default: False
LOADINGSCREEN_IMG_INCREMENT=50
Passed to viewer config but not currently referenced in JS. Reserved for controlling images shown per loading screen update.
default: 50
STACK_SPACING=0.09
Vertical spacing between images within a stack. Calculated in Houdini export if used. Acts as a multiplier for vertical spread.
default: 0.09

Max stack labels visible at once in the 3D viewer. Labels closest to screen center get priority. Rest are hidden for performance.

# image post processing
SHARPEN=False
Applies unsharp mask sharpening after resizing. Useful to recover detail lost during downscaling to SPRITE_SIZE.
default: False

How many surrounding pixels are considered for sharpening. Higher = broader area, more pronounced effect.
default: 1
SHARPEN_PERCENT=20
Strength of sharpening as a percentage. 0 = none, 100 = moderate, 500 = extreme.
default: 20
SHARPEN_THRESHOLD=3
Minimum brightness difference (0–255) before sharpening is applied. Prevents sharpening of subtle gradients/noise.
default: 3
GAUSSIAN_BLUR=False
Applies Gaussian blur to each image. Useful for softening harsh edges or depth-of-field style effects.
default: False

Radius of the blur kernel. Higher = more blurry. Can be a decimal (e.g. 0.5 for very subtle blur).
default: 2
# dithering
DITHERING=False
Reduces the color palette of each image using dithering patterns.
default: False
DITHER_MODE='custom_palette'
Dithering strategy. 'bw' = black and white only. 'color_reduce' = reduce to DITHER_COLORS colors. 'custom_palette' = map to closest in CUSTOM_PALETTE.
default: 'custom_palette'
DITHER_METHOD='ordered'
Algorithm for distributing quantization error. 'floyd_steinberg' = smooth diffusion. 'ordered' = geometric/retro grid. 'none' = hard color snapping.
default: 'ordered'
DITHER_COLORS=256
Number of colors to reduce to when DITHER_MODE='color_reduce'. Ignored for 'bw' and 'custom_palette'. Range: 2–256.
default: 256
CUSTOM_PALETTE=['#000000', '#FF0000', '#00FF00']
Hex colors to map to when DITHER_MODE='custom_palette'. Every pixel maps to the nearest color in this list. Ignored for 'bw' and 'color_reduce'.
default: ['#000000', '#FF0000', '#00FF00']

Are there folder names I cannot use?



When adding website content, do not name your folders any of the following, as they will not be processed.

This also means you can use these names for working directories — files inside them will be ignored. Using a geo directory is recommended for saving out models or other extra files.

venv, __pycache__, .git, fonts, spritesheets, images, backup, geo



How to add keywords to folders and files?



You can add a .keywords file to any folder or next to any image or text file. Most of the time you would add contact keywords so that when clicked, the user is taken to the about page.

project
green
eco
email


How do I deploy my stack?



It is highly recommended to first test on a copy of the website that contains only demo projects.



Before publishing, test your stack locally to make sure it renders as expected. You can set the global variable

PROCESS_IMG_LOWRES=True #True for lowres, False for original

in the global vars section of the Python file for faster processing. You can also set the resolution below it:



if PROCESS_IMG_LOWRES:
    DEFAULTS['SPRITE_SIZE'] = 32
    DEFAULTS['LABEL_SPRITE_SIZE'] = 32


This is also useful if you want all spritesheets at the same resolution.

Once testing is done, copy your folder into the final website.







What are some future plans?



  • Add global variable REVERSE_STACK=True/False to quickly change the direction of a stack's images.
  • Turn the Houdini file into an HDA.
  • Displacement settings per image — would make geometry 3D and closed, requires an additional spritesheet and more loading time.
  • Agents doing A* pathfinding on the stacks, with perspective camera highlighting.
  • Bug: large pieces of text are displayed too far above — they should all start from the same horizontal baseline.
  • Colored dots for HTML indication are unclear. Blue for .html_stops_here and green for .html_only_here are not good indicators when colored dots are enabled. A different shape or animation may help.
  • The "turn off labels" blue circle looks the same as the blue HTML dots — this should not be the case.
  • The submenu_close_delay global variable does not appear to be working — needs to be fixed.
  • Support array entries for COLOR_TO_TRANSPARENT so more than one color can be made transparent — currently limited to one. also array entries for treshold vars
  • Add a legend to the tree viewer so it is clear what the blue and green dots (.html_only_here and .html_stops_here) mean.
  • Wire nav system styling: the background is not rounded while the foreground is. The border color (blue, gray, or white) should also be consistent.
  • back and forth buttons on desktop need a makeover.
